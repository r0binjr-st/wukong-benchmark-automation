# Wukong Benchmark Automation

Программа на C# автоматически выполняет два прогона Black Myth: Wukong Benchmark Tool с разными настройками. Запускает сцену, читает результаты самого бенчмарка и закрывает его. Исходные настройки после работы восстанавливаются.

## Запуск

Нужны Windows x64, .NET SDK 10, Steam, установленный Benchmark Tool и [Microsoft Visual C++ Redistributable x64](https://aka.ms/vc14/vc_redist.x64.exe).

1. Один раз открыть бенчмарк вручную и закрыть его, чтобы появился файл настроек.
2. Открыть терминал в папке с `VkPlayPractice.csproj`. Все файлы проекта и папка `tessdata` должны оставаться рядом. При первом запуске .NET скачает пакет Tesseract из NuGet.
3. Запустить:

```powershell
dotnet run
```

Путь к настройкам программа ищет в библиотеках Steam. Если найти его не удалось, передать полный путь вручную:

```powershell
dotnet run -- "ПОЛНЫЙ_ПУТЬ_К_GameUserSettings.ini"
```

Steam должен быть запущен. Во время выбора меню не переключать окна, не перекрывать бенчмарк и не двигать мышь: программа читает изображение игрового окна и нажимает найденные кнопки. Работает с русским и английским меню; модели OCR включены в `tessdata`, распознавание выполняется локально. На ноутбуке проверка проводилась от зарядки.

## Настройки

- **CPU:** низкая графика, масштаб рендеринга 28.125% в INI, окно до 1920 × 1280. Эти настройки уменьшают работу видеокарты, чтобы снизить её влияние на FPS.
- **GPU:** высокая графика, масштаб 100%, разрешение основного экрана. Цель — высокая нагрузка на видеокарту.

В обоих профилях выключены VSync, ограничение FPS, генерация кадров и полная трассировка лучей. Разрешение адаптируется под экран. Фактически применённые настройки берутся из результата игры и выводятся в отчёт.

## Результаты и восстановление

После запуска в `results` создаётся папка с датой и временем. В ней:

- `report.html` — открыть в браузере: FPS и загрузка GPU обоих профилей в одной таблице, информация о ПК, подробные настройки и ошибки в раскрывающихся блоках;
- `report.txt` — короткая текстовая сводка;
- `cpu-result.json` и `gpu-result.json` — исходные результаты бенчмарка;
- `cpu-applied.ini` и `gpu-applied.ini` — применённые настройки;
- `cpu-menu` и `gpu-menu` — снимки распознанных экранов и текст OCR. При ошибке здесь сохраняются последний снимок и описание;
- `ocr-native.log` — служебные сообщения движка распознавания.

Окончание сцены определяется по новому файлу результата в `%TEMP%\b1\BenchMarkHistory\Tool`.

Перед изменениями создаётся `GameUserSettings.ini.backup`. После работы или обработанной отмены через `Ctrl+C` восстанавливается оригинал. Если программа была принудительно завершена и копия осталась, нужно закрыть бенчмарк, скопировать `.backup` поверх исходного INI и только затем удалить копию. `original.ini` из папки проекта не используется.

## Проверка

Оба прогона и восстановление настроек проверены на i7-13700H, Intel Iris Xe, 16 GB RAM: CPU-профиль — 36 FPS, GPU-профиль — 6 FPS. Настройки восстановились.

В CPU-прогоне GPU был загружен на 97%, поэтому преимущественная нагрузка на процессор пока не подтверждена. Этот профиль нужно проверить на ПК с более мощной видеокартой. В GPU-прогоне загрузка составила 99%.

Меню определяется по тексту на двух снимках, кнопка нажимается по найденным координатам. После подтверждения проверяется только область найденной кнопки; чёрные кадры загрузки пропускаются. Сборка, русские скрины игры, английские тестовые экраны и логика исчезновения диалога проверены. Полный запуск исправленной OCR-версии на Windows прошёл успешно. При ошибке снимок остаётся в папке прогона.
